# AGENTS.md / AGENT.md

Operating guidelines, rules of engagement, and skills for AI agents and coding assistants working on SmartMeal.

---

## 1. Documentation-First Mandate (CRITICAL)

Before and after performing any technical work, all AI agents and developers **MUST** observe the following documentation protocols:

### 1.1 Pre-Task Requirement (Read Before Writing Code)
On starting any coding, debugging, or architectural task, you **MUST** read the relevant documentation in `docs/`:
- **Architecture & Subsystems**: `docs/architecture.md` (component layout, inter-service networking, K8s Gateway API routing).
- **API Reference**: `docs/api.md` (or `docs/api-reference.md`) (endpoint contracts, auth requirements, payloads).
- **Database & Schemas**: `docs/database.md` (table definitions, relationships, migration history).

### 1.2 Post-Task Requirement (Synchronize Docs on Changes)
Whenever you introduce changes that affect schemas, APIs, architecture, or services, you **MUST immediately update the corresponding docs in `docs/`**:
- **Adding or modifying database tables, columns, or relations** $\rightarrow$ Update `docs/database.md`.
- **Adding or modifying endpoints, request/response models, or error codes** $\rightarrow$ Update `docs/api.md`.
- **Modifying service architecture, deployment topologies, ingress/routing, or environment variables** $\rightarrow$ Update `docs/architecture.md`.

*Never leave documentation out of sync with code.*

## 2. Commit & Release Rules (Strict Conventional Commits)

All commits generated by AI assistants, agents, or VS Code AI extensions **MUST** adhere to Conventional Commits. The CI/CD workflow (`.github/workflows/main.yml`) automatically derives release tags and semantic versions based on these rules:

### 2.1 Commit Structure
```text
<type>(<optional scope>): <short description>

[optional body]

[optional footer(s)]
```

### 2.2 Semantic Version Bump Table
| Bump Level | Commit Pattern / Path Condition | Workflow Logic | Example |
| :--- | :--- | :--- | :--- |
| **Major (`X.0.0`)** | `feat!: ...` or body/footer containing `BREAKING CHANGE:` or `breaking:` | Triggers `major_pattern` in semantic-version action | `feat!: replace legacy auth with OAuth2 PKCE` |
| **Minor (`X.Y.0`)** | Starts with `feat:` **OR** any commit modifying files in `Server/**` or `AI/**` | `minor_pattern` or `dorny/paths-filter` backend filter | `feat(client): add macro tracking summary`<br>`chore(server): update pgsql connection pool` |
| **Patch (`X.Y.Z`)** | Starts with `fix:`, `chore:`, `docs:`, `refactor:`, `perf:`, `style:` (without changes to `Server/` or `AI/`) | Increments patch version | `fix(client): handle null ingredient image error`<br>`docs: update database schema reference` |

## 3. VS Code AI Assistants & IDE Extensions Policy

When interacting via VS Code AI extensions (GitHub Copilot, Roo Code, Cursor, Cline, Claude Dev):

1. **No Unapproved Pushes or Destructive Actions**:
   - Assistants must **NEVER** run `git push`, force pushes (`git push --force`), or destructive git commands (`git reset --hard`, `git clean -fd`) without explicit human instruction.
   - Do not commit changes unless specifically requested by the user.
2. **Formatting & Messaging**:
   - Keep assistant explanations clear, structured, and concise. Avoid superfluous boilerplate.
   - When suggesting commits, generate Conventional Commit messages matching Section 2.
3. **Workspace Boundaries**:
   - Respect the separation of concerns across subprojects: `Server/`, `AI/`, `Client/`, `ClientMobile/`, `infra/`.
   - Do not mix frontend dependencies into backend projects or vice-versa.

## 4. Project Skills Reference & Activation Guide

SmartMeal provides dedicated skills in `.skills/`. Agents should invoke and reference these skills whenever working in their corresponding domains:

### 4.1 `.skills/frontend-design/SKILL.md`
- **When to Invoke**:
  - Modifying React 19 components, hooks, services, or styling in `Client/`.
  - Updating Flutter widgets, screens, providers, models, or Dio configuration in `ClientMobile/`.
  - Designing responsive layouts, accessible UI controls, toast alerts, or token management in `Client/src/services/api.js`.
- **Key Focus**: React 19 standards, Tailwind breakpoints, Axios error interceptor envelopes, Flutter clean feature architecture, and secure storage for JWTs.

### 4.2 `.skills/backend-design/SKILL.md`
- **When to Invoke**:
  - Developing features or endpoints in `Server/`.
  - Working across `PresentationLayer`, `Service`, `Repository`, `DataAccessLayer`, or `BusinessObject`.
  - Writing EF Core queries, migrations, DTO request/response models, or Swagger configurations.
- **Key Focus**: Clean Architecture separation (no DbContext in controllers), `.AsNoTracking()` for queries, avoiding N+1 loops, standardized API envelopes, and `dotnet ef migrations` commands.

### 4.3 `.skills/ai-design/SKILL.md`
- **When to Invoke**:
  - Modifying inference scripts, configurations, or endpoints in `AI/` (`smartmeal-predict`).
  - Updating ONNX models, YOLO image preprocessing (Pillow/NumPy), or post-processing (NMS/bounding boxes).
  - Optimizing Docker packaging, container memory consumption, or health check routes.
- **Key Focus**: Stateless microservice execution, ONNX Runtime session pooling, vectorized NMS coordinate rescaling, and minimal image containerization.
